# Codebase ⇄ Documentation Audit

## Context

You asked: *"is everything up to date as per the `update/` folder and `update/changes/` folder?"*

The audit compares **what's in the docs** against **what's actually in the repo**. Two documentation sets coexist:

- **`update/`** — describes **ClarityAI v0.1** (web-first Socratic tutor, Gemini 2.0, FastAPI middleware). Claims **Phases 1–7 complete**.
- **`update/changes/`** — describes **LUMOS v4** (a *pivot* to a hardware-first stack with Groq + Cartesia + Redis + pgvector + a brand-new `lumos-backend/` layout). Marked **pre-build** across all 7 phases.

Headline: the **ClarityAI v0.1 codebase is real and matches its docs**. The **LUMOS v4 pivot is documented but virtually unbuilt** — zero Groq, Cartesia, Redis, or the planned `lumos-backend/` module structure exists.

## 5. Bottom line

- **Up to date with `update/` (v0.1)?** Largely yes. One stale doc (`IMPLEMENTATION_PLAN.md`) and one off-topic doc (`PROJECT_CONTEXT.md`). Runtime hygiene items in `KNOWN_ISSUES.md` still apply.
- **Up to date with `update/changes/` (v4 pivot)?** **No** — the pivot is documented but not started. Database foundation is partially aligned (devices, pairing, exam_track column, pgvector); everything else (Groq, Cartesia, Redis, MSM cache, orchestrator, classifier, formatters, R2, two-track routing, latency instrumentation) is unbuilt.

**v4 is confirmed as the actual product direction.** The repo therefore sits at "end of v0.1, before v4 build starts." Concretely, the remaining gap to ship v4 is:

1. **Backend rewrite** — flat `backend/` → modular `lumos-backend/` (gateway, orchestrator, providers, classifiers, formatting, storage, workers, schemas, prompts).
2. **LLM stack swap** — Gemini 2.0 Flash → Gemini 2.5 Flash (Turn 1) + Groq Llama 3.3 70B (Turn 2+) + Gemini 2.5 Pro (escalation) + Cartesia Sonic TTS.
3. **State layer** — add Redis (MSM cache, attempt counters, 3-layer Gemini context cache, session profiles).
4. **DB extensions** — `turns`, `question_attempts`, `memories` (pgvector) tables on top of migration 002.
5. **Pipeline pieces** — query classifier (6-type taxonomy), nudge logic (attempt-count → HINT/FULL/DIRECT), validator (confidence gate + voice/TFT/LaTeX checks), two-track formatter, Google Search grounding for conceptual.
6. **Blob storage** — Supabase Storage → Cloudflare R2 (per LUMOS spec).
7. **Hardware target shift** — ESP32-CAM firmware → ESP32-S3 + INMP441 + OV5640 + MAX98357A + ILI9341 + WS2812B (matches HARDWARE_CONTEXT.md frame protocol exactly).
8. **WebSocket consolidation** — drop `/ws/client/{id}` and `/ws/hardware/{id}`; keep only `/lamp/ws` with the LUMOS binary-frame protocol and device_jwt auth.
9. **Latency instrumentation** — TTFT, total_ms, cost_usd per turn; targets <1.5s (Turn 1) and <500ms (Turn 2+).

This audit is the deliverable — no doc or code edits made. Use it as the input when you're ready to scope the v4 build.

## Addendum — Phase 0 build completed (2026-05-26)

The user approved a Phase 0 scope (foundation only) on the day after this
audit and the build landed the same day. State now:

- ✅ **WebSocket consolidation (#8)** — only `/lamp/ws` remains. `/ws/client/{id}` and `/ws/hardware/{id}` deleted. Close codes split into 4401 (bad JWT) / 4402 (revoked device) per LUMOS spec.
- ✅ **Hardware target shift (#7)** — new ESP32-S3 firmware in `firmware/tutor_lamp/` (config, provisioning + NVS, net_ws WebSocket client with backoff + heartbeat, main sketch). Old ESP32-CAM firmware archived to `firmware/legacy/`.
- ✅ **JWT alignment** — `iss` is now `lumos-auth`, claims carry `ver=1`. Existing pre-pivot tokens are invalidated (acceptable; no prod users yet).
- ✅ **Web-app deprecation** — ~25 v0.1 routes/hooks/components/lib files removed; deps trimmed (`@google/generative-ai`, `framer-motion`, `react-markdown`, `rehype-katex`, `remark-math`, `remark-gfm`, `@tailwindcss/typography`, `@notionhq/client` dropped). `npm run typecheck && lint && build` all pass; web app is now 6 routes (`/`, sign-in/up, devices, pair/[code], clerk webhook).
- ✅ **Phase 0 tests** — 15 pytest cases green (auth, registry, frames, WebSocket end-to-end incl. PING/PONG, AUDIO_END stub, CANCEL, 4401, 4402).
- ⏳ **LLM stack (#2)**, **state layer (#3)**, **DB extensions (#4)**, **pipeline (#5)**, **R2 (#6)**, **latency instrumentation (#9)** — all unblocked and now scheduled for Phases 1–6 per [`update/IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md).
